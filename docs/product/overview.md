# 产品与范围

面向创作者、产品负责人和扩展开发者，说明目标用户、首版能力、典型使用场景与支持范围。

## 1. 定位与用户结果

Riloom 是本地优先、可编程的二维角色制作工作台，首个目标生态为 Live2D。创作者能够从自己的分层素材建立可编辑角色，控制图层、形变、表情、换装、动作和物理，并导出脱离制作服务运行的作品。

| 使用角色 | 任务 | 可观察结果 |
| --- | --- | --- |
| 美术与模型制作者 | 分层、补画、拼接、布网、绑定、关键形 | 原始素材可追溯，候选可比较，编辑可撤销 |
| 动作与表现制作者 | 编排表情、动作、换装及物理 | 逐帧、逐轴观察相互作用，可定位短暂缺陷 |
| 自动化调用者 | 通过 MCP、CLI、SDK 批量制作 | 同一输入契约、可查询回执、冲突保护、恢复续作 |
| 模型使用者 | 在独立播放器或目标软件使用模型 | 运行包自包含，实际表情、动作和追踪映射正确 |
| 扩展开发者 | 新增导入器、工位或导出器 | 使用版本化接口和合成一致性套件完成接入 |
| 开源维护者 | 审查变更、发布和处理缺陷 | 可复现构建、可追溯验收、明确许可与支持范围 |

## 2. 首版完整能力范围

| 能力域 | 首版设计要求 |
| --- | --- |
| 工程与素材 | 新建、打开、保存、版本化工程包；PSD、PNG 导入；来源与许可字段；像素遮罩、分组、可见性和裁切 |
| 直接编辑 | 图层、网格、UV、父控制、参数、关键形、遮罩、绘制顺序、轨道和物理组 |
| 制作工位 | 全画框外部补画准备与回导、可选图像提供方、拼接检查、拓扑、控制、关键形、连接、衣口分层、动作、物理、轨迹和返修 |
| 表现系统 | 任意数量的表情与衣装，互斥组、覆盖与混合规则；独立嘴型和开口量；动作与追踪仲裁 |
| 预览 | 同一工程求值与渲染实现服务 Studio 和便携预览；网格、保护选区、遮挡、轨迹及差异观察 |
| 自动化 | MCP stdio、CLI、TypeScript SDK；与 Web 共用命令与任务服务 |
| 持久任务 | 队列、进度、取消、检查点、重启恢复、预算及产物登记 |
| 原生适配 | 版本化 Cubism 转换接口、VTS API 联调与运行配置生成；按适配器能力提供真实输出 |
| 交付 | 可编辑工程包、离线 Web 运行包、目标软件运行包、独立验收资料 |
| 维护 | 数据迁移、备份恢复、资源盘点、可回收数据预览和可追溯发行 |

任意模型结构通过对象关系和参数定义表达。模板只提供起点，默认人体部件、固定三套衣装、固定嘴型或固定参数名称均不得成为核心约束。合成验收包含非人形、非对称、多附肢和零衣装工程。

第一版采用单机单用户工作区。多人协作编辑、云端托管、公共插件市场、移动端完整建模、三维建模和通用视频剪辑作为范围外能力，新增时另立需求。可选图像生成服务通过受控提供方接口接入。

## 3. 核心使用场景

- **S1 从素材到工程**：选择本地 PSD → 查看逐层导入结果 → 建立网格及父控制 → 保存并重新打开，像素、几何、UV、遮罩和层级保持。
- **S2 自由制作与自动化协作**：人工修改对象 → MCP 基于旧修订提交候选 → 冲突保留候选 → 比较新旧内容后重新准备，人工修改完整保留。
- **S3 表现编排**：切换表情与衣装 → 选择嘴型 → 追踪嘴部开合 → 播放单次动作 → 回到选定待机，所有通道按工程规则组合。
- **S4 缺陷返修**：在具体时刻标记穿层或连接问题 → 保存受影响对象与画面 → 生成修复候选 → 应用 → 重放原场景及相关相邻采样 → 记录数值与视觉结论。
- **S5 独立交付**：选择交付内容 → 展开完整依赖 → 转换及核验 → 组装新目录 → 在制作服务关闭、网络断开的条件下使用运行包。
- **S6 可恢复制作**：长工位执行中退出客户端或服务中断 → 重新连接 → 查询原任务 → 复用完成步骤 → 只恢复受影响步骤。

~~~mermaid
flowchart LR
  A[导入素材或创建工程] --> B[分层与组件绘制]
  B --> C[网格与控制]
  C --> D[关键形与行为]
  D --> E[候选预览与检查]
  E --> F[原子应用]
  F --> G[目标软件核验]
  G --> H[组装独立交付]
  E --> I[定位缺陷]
  G --> I
  I --> B
~~~

人工可以直接编辑任一对象，工位配方为选定对象生成候选，允许跳过无关工位、调整顺序、保存个人配方。

## 4. 支持目标与质量目标

核心服务目标平台为 Windows 11 x64、Ubuntu 24.04 x64、macOS arm64；Studio 目标为 Chromium 和 Firefox 的发布时当前与前一主版本。原生适配首个目标为 Windows 11 上明确登记的 Cubism 与 VTS 版本，平台支持按适配器分别登记。

首版可用判据是 S1—S6 的实际链路及 [21 项主需求](requirements.md)满足其验收合同。独立运行、美术画面、目标软件、工程完整性分别有结果记录。性能采用[质量文档](../testing/strategy.md)的模型负载和设计预算。
