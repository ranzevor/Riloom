# 测试与验收方案

面向测试设计和功能验收，给出输入、独立预期、故障注入位置和性能预算。

## 1. 验收方法

每项检查固定需求、候选内容身份、配置、输入、环境、步骤、独立期望、结果及原始产物。功能、结构、数值、视觉、目标软件和交付采用分别登记。该文档定义未来实现的验收合同；执行结果随具体候选保存。

关键机制必须有正常输入、直接破坏不变量的反例和相邻合法输入。生成基准值不能调用同一被测算法自动取实际输出；像素、几何和混合使用可手算的非对称合成样本或独立参考求值。

### 空工程创建的执行步骤

1. 在空工作区中指定新的空目录和 1024×1024 像素画布，以固定请求身份创建工程。
2. 读取工程标识、初始修订和默认画布，确认素材与绘画集合为空，工作区仅登记该次创建的一个工程。
3. 关闭并重新打开工程，核对工程身份和初态，再重投同一请求，确认取得原回执和同一工程。
4. 分别在目录发布前、完整目录发布后且工作区登记前中断服务，再按原操作恢复。完整目录校验通过时补齐登记与回执，不完整创建按操作归属清理并返回创建失败。
5. 使用无效画布和非空目标目录重复输入，确认输入被拒绝且工作区保持有效登记。修正对应输入后以新请求重新创建。

### 图像、分组合成与遮罩的独立预期

T01 检查原文件、原始解码、工作副本和重开结果，T08 对照 Studio/离线播放器及独立数值参考，T15 检查目标回读和输出画面。原始保留按字节和通道精确比较，转换副本按固定 ICC 配置的独立参考比较，渲染在线性预乘 RGBA 与固定 sRGB 输出两处取样。颜色实现、像素格式及各阶段容差在 V-RENDER-01 固定后用于对应候选。

| 合成输入与步骤 | 独立预期与直接反例 |
| --- | --- |
| 透明背景，Normal 隔离组内不透明红层与上方不透明蓝层重叠，组透明度 0.5 | 重叠区预乘 RGBA=(0,0,0.5,0.5)。逐子层乘透明度会错误得到 (0.25,0,0.5,0.75) |
| 上例置于透明度 0.5 的外组，并改变组内层号 | 外组再施加一次透明度，重叠区 Alpha=0.25。组内层号改变对应组内颜色，组作为整体保留父级位置 |
| P 只覆盖左半，S 全幅且由 P 遮罩，T 全幅且以 S 为遮罩源 | S 与 T 均只在左半可见。从 S 自身遮罩前采样会错误使 T 全幅可见 |
| 不透明源位于透明度 0.5 的祖先组内，目标位于组外，分别选择 local/global。另将源自身隐藏 | local 源覆盖率为 1，global 为 0.5。源自身隐藏时两者均为 0。两个 0.5 输入的 intersect 为 0.25，union 为 0.75 |
| 带 Display P3 ICC 的纯红 PNG 与 Alpha=128/255 的 sRGB 纯蓝 PNG | 原文件、原始通道及 ICC 精确保留。默认超色域策略拒绝应用，显式 clip-srgb 得到 sRGB 红工作副本。蓝叠红后的线性 RGBA=(127/255,0,128/255,1)，sRGB RGBA8 最近值量化为 (187,0,188,255) |

另用色域内的非对称多色样本，对照独立色彩实现预先生成的固定期望，防止忽略源配置也通过纯红裁切例。无配置 sRGB、低 Alpha 和合法空分组可正常导入。缺失遮罩源、自引用、跨组依赖环分别被拒绝，候选不产生成功编辑。完整无环链不受显示层序限制。T15 对不能等价表达的合成效果定位具体对象，明确选择烘焙后再核对对应完整候选。

### 本地服务发现与授权检查

T12 核对 IPC 与各入口的授权语义，T18 覆盖伪端点与能力滥用。M1 先验证其本地服务切片。

1. 服务持锁后发布发现信息，合法 CLI/MCP 客户端经本地启动授权交接和握手连接指定工作区。核对实际对端、工作区、启动世代及会话的工程和命令范围，授权查询与写入分别按范围执行。
2. 分别替换发现端点、工作区、进程实例和启动世代。连接拒绝发生在命令登记前，无编辑、任务或外部派发。协议版本不相容按握手规则拒绝，正确版本及正确对端可连接。
3. 重启服务、撤销客户端授权、恢复接替工程后，重投旧能力请求命中 PERMISSION_DENIED。另在请求受理后、排队步骤派发前撤权，确认该步骤停止派发并按实际效果结束。重新取得当前授权并读取新状态后可执行对应命令。发现记录、工程包及日志中均无引导或会话凭据。

### 命令与事件的交错检查

以下步骤分别纳入 T09、T10、T12 和 T13，沿用对应需求与场景编号。

1. 用已注册的 "1.0.0" 调用合成命令并核对回显。使用新请求身份，将 commandVersion 改为整数时命中输入错误，改为未注册的合法 SemVer 时命中 UNSUPPORTED_VERSION，两种输入均不登记操作或派发任务。
2. 两个客户端同时提交同作用域、同 requestId 的同一编辑或后台任务。编辑只产生一个修订，任务只建立一个 job 和原受理回执。在受理事务提交后、首次派发前中断，再按原请求查询和恢复，jobId 保持一致。同请求改输入命中 REQUEST_ID_REUSED。
3. 分别让取消登记先于、后于本地任务最终发布提交。前者阻止最终发布，回收后为 cancelled。后者保留 succeeded 与原结果。使用陈旧任务版本取消时返回 REVISION_CONFLICT，读取仍得到原终态。另取消已有成功前置步骤的任务，确认这些步骤与产物保留，剩余步骤停止。
4. 在读取工程状态之前、之后、建立订阅之前以及重放赶上实时进度时分别提交编辑。状态读取和游标属于同一读事务，游标之后的编辑均可重放，重复通知按流和序号去重。首次打开、重连及前台恢复执行相同规则。游标过期时重新读取一致状态与新游标，再提交一项编辑，确认增量继续到达。

### 草稿保存、回执与恢复检查

T13 使用两个编辑会话和可控请求屏障，T12 对应核对各入口的草稿封套与结果。

1. 创建独立草稿，保存基线与编辑代次 g1，模型修订和状态身份保持。在其回执到达前继续编辑为 g2，确认 g1 回执后仍有 g2 待保存。完成 g2 后再送达旧回执，界面保持 g2 的确认版本。保存失败时保留输入与具体重试入口。

### 备份恢复、身份接替与外部任务检查

T22 在隔离工作区和合成外部目标中执行，T10 核对同存储重启与备份恢复的不同接续规则。

1. 活跃编辑与资源回收期间执行一致性备份，核对备份模型、账本与固定读视图相符，全部资源闭包在恢复前完整。原工程继续编辑，备份内容保持其固定视图。
2. 在外部步骤仍为 queued 时完成备份，随后让原工程派发并完成该步骤，再从备份恢复。恢复任务先进入 reconciling，外部动作次数保持为 1。分别使用可查询目标及无查询能力目标，前者按原操作补齐结果，后者保持未决。原取消意图继续阻止派发。
3. 备份前外部步骤 A 已成功，纯计算 B 待执行。恢复复用 A 的有效结果，核对费用与原执行前提后显式恢复 B，A 调用次数保持为 1。另以明确未发生的外部步骤验证当前授权下显式恢复才派发。备份截止后消费不被清零，核对前外部可用额度为 0。
4. 原工程持有身份锁时，在另一工作区打开异目录副本，确认副本仅隔离读取。释放原所有者后接替登记，projectId 保持而 storageGeneration 更新，当前工作区只路由到接替目录。旧能力拒绝，当前授权可读取备份模型并按恢复屏障续作。
5. 将选定历史交换包导入独立工作区，确认新 projectId、原对象 ID 与模型语义、素材及逆操作保持，旧任务、请求账本、外部操作和授权不成为可执行登记。作为相邻对照，同存储崩溃重启沿原账本接续，同一请求仍关联原结果。

### 交换包与扩展兼容检查

T22 使用可再分发的最小工程包与合成扩展数据。

1. 包含根清单、project.json、rights.json 和完整依赖，核对 files 与载荷常规文件集合一致。将根清单自身加入 files，再分别增加未列文件、删载荷、重复名称、修改长度或摘要，确认 DATA_CORRUPT 指向具体条目。合法目录条目按目录规则接受。
2. 合成未知可选扩展引用一个网格和一份独立素材，payload 含不被核心解释的字段。往返后核对 payload、声明与依赖字节，修改无关对象和显示名后仍保持对应内容。
3. 删除依赖对象或改变其网格、UV、父控制和参数定义时，缺处理器返回 UNSUPPORTED_FEATURE。相容处理器提供更新后可提交。另显式移除该可选扩展并修改对象，再撤销，核对完整扩展与素材可恢复。
4. 使用未知必需扩展和未知引用类型，核对受限读取能力。查看、校验和完整导出可执行，会改变原包成员的编辑或维护返回 UNSUPPORTED_FEATURE，原包成员完整。已识别封套缺失声明字段或声明目标缺失时返回 DATA_CORRUPT，并定位具体依赖。

### 资源发布与回收交错检查

T22 在自有合成存储中固定保留策略，通过屏障安排以下顺序。

1. 准备候选并结束其生成任务，保持候选可用且未应用。回收后其来源和派生素材完整。显式丢弃候选后保留文件读取占用，回收仍返回保留项，流关闭且满足保留条件后该资源可被回收。
2. 分别在发布预留登记后、内容文件发布后但引用提交前暂停发布者，同时执行回收。回收按预留和存储锁等待或保留该项，发布提交后可用引用完整。发布失败时仅按已结束操作及保留条件处理孤立文件。租约过期而旧执行者仍存活时保留输入占用，确认退出且核对在途结果后再解除。
3. 在删除计划生成后新增草稿、历史逆操作或任务引用，核对执行时保留对应资源。再让删除者先取得锁并登记 deleting，新引用等待或收到 RESOURCE_BUSY，资源实际回收后旧引用返回 RESOURCE_GONE。
4. 分别在删除意图保存后、文件删除后但注销前、注销后但回执返回前中断服务。按原操作恢复逐项核对，已完成条目复用，同请求返回原回执，异步结果通过原 jobId 查询。重新发布同一内容前完成原删除意图，旧维护操作重投仍关联原结果。
5. 注入有效保留引用对应的缺失文件，确认 DATA_CORRUPT。释放所有引用的合法相邻样本按计划回收。对含未知扩展的工程核对声明依赖或完整原包保留集合进入闭包。

## 3. 故障注入位置

事务：素材临时写、素材发布、数据库提交前、提交后应答前、回执读取。任务：意图登记、派发、外部成功、回执持久化、检查点发布、取消登记、Worker 退出。交付：文件写入、清单生成、校验、候选目录发布。

求值检查点覆盖状态写入和索引更新边界。模型安装覆盖暂存完成、旧目录移出、新目录发布、目标回读和结果保存边界。

备份覆盖固定读视图、资源闭包保留、恢复屏障、身份锁接替与登记发布边界。IPC 覆盖发现记录替换、握手、服务重启和授权撤销。

资源回收覆盖发布预留、引用提交、逐项删除意图、文件删除与资源注销边界。追踪插件覆盖缓冲满、断连、输入释放和新流接入边界。

补画覆盖准备产物发布、返回素材固定、回导草稿版本与候选共同发布、丢弃和迟到提供方结果。

草稿覆盖保存确认、固定应用前缀、模型提交和终结标记提交边界，历史覆盖组追加、封口与游标变更边界，列表覆盖集合版本变化与页面返回交错。

每个位置记录工程修订、对象完整性、外部效果次数、未决操作、恢复后的首个动作和自有进程存活情况。失败测试必须在目标判据处失败，不能以语法错误、夹具未加载或工具启动失败充当成功拦截。

## 4. 性能设计预算

以下为实现目标，M1 固定参考设备、OS、浏览器及驱动后执行测量。预算变更保留理由和影响，不能根据失败结果临时放宽。

参考负载 P1：1920×1080 视口、400 绘画网格、10 万顶点、100 参数、40 物理组、4 张 2048² RGBA8 纹理、固定 60 秒动作。基准夹具采用可再分发的合成角色。

| 项目 | 设计目标与测量 |
| --- | --- |
| 播放响应 | 60 Hz 目标，暖机后 60 秒帧时间 p95 ≤16.7 ms；记录 p99 与掉帧 |
| 输入反馈 | 本地参数输入到首个对应画面 p95 ≤50 ms |
| 小型持久编辑 | P1 单对象编辑含回执 p95 ≤250 ms；图像重算按后台任务计 |
| 打开工程 | 本地 SSD、冷缓存 P1 ≤5 s；首次构建与启动分开记录 |
| GPU | renderer 自有分配 ≤256 MiB；实际驱动数据和估算分别记录 |
| 常驻内存 | service + Studio 稳态 P1 ≤1 GiB；重计算 Worker 默认预算 2 GiB |
| 取消 | 协作 Worker 2 s 内响应；5 s 宽限后回收自有任务树；外部效果另核 |
| 泄漏 | 20 次工程切换并释放旧视口后，存活纹理/缓冲数量与当前工程第一次稳定状态相同；同时记录内存平台和总预算 |
| 输入与磁盘 | 派发前估算最坏解码和输出峰值，无法容纳则不开始写入 |

4 张纹理含完整 mipmap 的像素存储约为 85.3 MiB，剩余 GPU 预算覆盖渲染目标、遮罩和缓冲；驱动额外占用另行测量。设备配置和实际统计随记录保存，系统总显存占用与本进程分配分别呈现。

## 5. 开发检查

支持矩阵记录所覆盖的具体平台、运行时和浏览器版本，CI 作业固定相应版本。

- 快速变更检查：格式、Lint、严格类型、Schema 示例、模块依赖、受影响单元/属性/契约测试。
- 入口或持久化变更：增加真实协议、存储故障与恢复、跨入口集成。
- 渲染或表现变更：增加像素/轨迹参考、相关视觉评审和受影响目标软件核验。
- 打包或平台变更：从最终安装包执行干净环境安装、权限、资源与独立运行。
- 公开发行：核完整交付清单、许可通知、秘密、支持矩阵和实际发布权限。

已经通过且对象、环境和证明命题未变化的检查复用原记录。变更影响分析指出需要补验的节点与消费者；不因换轮、整理文档或进入新阶段重复全部检查。
