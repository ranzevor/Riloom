# 项目治理与发行

面向项目维护者与贡献者，说明职责、仓库组织、审阅、版本发布和支持流程。

## 1. 职责与决策

项目负责人决定 Riloom 的产品范围、官方软件发行、发行渠道与软件对外承诺。项目权利主体在其有权许可的代码、文档、图形和品牌材料范围内确定许可。设计与开发负责人承担软件方案、实现和缺陷修复。软件验收负责人判断软件功能、兼容与安装结果，软件发行负责人组织对应软件文件集合的发布。

作品权利主体或其授权验收者决定用户作品的采用。工程操作者按工程、素材、费用和目标软件的实际授权执行制作与交付。作品交付流程见[软件适配与交付](../reference/integrations-and-delivery.md)，外部调用与数据处理见[安全设计](../security/design.md)。

项目新增平台、服务适配和云端处理能力通过需求变更确定。同一主体兼任上述职责时，分别按各项职责的对象与授权范围执行。

## 2. 仓库与内容组织

原创仓库名为 Riloom，保留品牌大小写。npm 包建议使用 @riloom/*，实际发布前检查命名空间和授权。托管平台采用 GitHub，仓库归属项目负责人授权的账号。包命名空间在实际发布时核对归属及权限。

[项目首页](../../README.md)提供中文入口，[英文首页](../../README.en.md)提供对应英文导航。[文档总览](../README.md)按用途分配产品、架构、参考、交互设计、安全、测试与项目文档。文档修订由版本控制管理，同一主题使用一个当前正文入口。

GitHub 仓库 Issues 使用[缺陷报告](../../.github/ISSUE_TEMPLATE/defect.md)和[变更建议](../../.github/ISSUE_TEMPLATE/proposal.md)模板接收反馈，提交修改使用[Pull Request 模板](../../.github/pull_request_template.md)。安全问题采用 GitHub 私密漏洞报告，流程见[安全报告](../../SECURITY.md)。贡献要求、版本政策、社区处理和许可从项目首页进入。

### 社区处理

项目协作遵循[行为准则](../../CODE_OF_CONDUCT.md)。维护者负责处理相关报告和复核请求。

维护者对普通问题说明分类、处理状态和关闭原因，重复报告关联到既有问题。材料许可与分发范围见[许可与分发](licensing.md)。

## 3. 贡献与审阅

文档与设计修改按[贡献指南](../../CONTRIBUTING.md)准备，提交消息遵循其中的类型、范围和中文主题约定。变更采用短生命周期分支与聚焦 PR，固定目标基线并提供完整差异。作者检查与维护者审阅分别执行，候选变化后复核受影响内容，合并前确认目标分支、已审内容、必要检查及材料接收条件。

默认分支为 `main`，通过 Pull Request 集成变更。`Documentation checks` 为文档检查项，`Engineering` 按 Windows、Linux 和 macOS 检查构建、类型、格式和行为，[CODEOWNERS](../../.github/CODEOWNERS)指定维护责任。平台规则要求检查通过，并限制直接推送和强制推送。审阅安排按实际参与者确定，独立技术审阅与平台批准分别处理。

跨模块契约变化同时更新需求、Schema、SDK、文档和相关测试。涉及产品范围或材料许可的变更，按[职责与决策](#1-职责与决策)确定决策主体。

## 4. 版本与发布

设计文档随 `main` 分支维护，通过提交定位具体修订。软件发行使用独立版本号及发行说明。

对外软件包采用统一 SemVer，公开 API 包含命令、SDK、工程格式、插件协议与 CLI 机器输出。预发行从 0.x 开始，破坏性变化仍提供明确迁移说明。工程格式主版本和插件协议版本独立登记；相同发行版本的文件不可替换。

发行流程从受版本控制的公开文件集合开始，按以下顺序执行。

固定源与锁文件 → 受影响门禁 → 干净环境构建 → 生成 SBOM、文件清单及摘要 → 核许可与通知 → 安装候选并执行交付合同 → 准备发行说明 → 获准发布 → 从分发渠道回读身份。

公开 CI 对外部 PR 使用无秘密运行器；原生测试和签名发布使用受控环境。签名或证明材料绑定实际构建对象；软件发行负责人发布前核对实际结果和完整文件集合。

## 5. 维护与支持

当前维护对象是 `main` 分支上的项目设计、本地工程编辑能力、文档和开发检查工具。仓库维护者通过 Issues 接收问题，通过 Pull Request 接收修改，按实际影响和复现情况安排处理。安全报告使用[私密渠道](../../SECURITY.md)。

每次发行登记支持平台、目标软件版本、已知具体问题和安全修复入口。稳定工程格式保留明确的迁移读取能力；弃用给替代入口、影响对象和退出版本。维护状态、负责渠道及响应安排随版本发布。

问题按可复现输入、源版本、触发步骤和实际结果登记。修复按触发步骤重现问题，并检查受影响功能。用户工程上传为主动选择，提供合成最小复现优先路径和敏感文件检查。
