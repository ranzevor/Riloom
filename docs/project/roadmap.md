# 实施路线图

面向项目负责人和开发者，按模块依赖安排实施切片、技术验证与阶段退出条件。

## 1. 阶段与退出条件

按依赖推进，每个阶段交付可观察的纵向流程；功能数量与任务数量不充当完成比例。

| 阶段 | 实施范围 | 退出条件 |
| --- | --- | --- |
| M0 项目设计 | 产品、数据、架构、接口、工作台、许可、质量与实施方案 | 文档完整、需求/验收/阶段关联闭合，需决策事项具体 |
| M1 工程底座与高风险验证 | contracts/core/storage/application。真实 SQLite 事务、服务发现与授权握手、备份恢复屏障、MCP 桥、最小 Studio。原生转换路线验证 | [创建工程](../product/requirements.md#req-01-1)→草稿编辑与保存→完整应用→冲突→重启查询回执可执行。跨平台工具链锁定。D-NATIVE-01 有准确可行路线或明确受影响范围 |
| M2 素材与自由制作 | [PSD/PNG 导入](../product/requirements.md#req-01-2)、全画框补画往返、网格/UV、控制、多轴关键形、工位与候选、共享渲染及统一视口 | S1、S2 的制作链路及相关故障合同通过。非人形合成工程可用 |
| M3 表现与返修 | 表情/衣装/嘴型、曲线、物理、随机待机、轨迹、缺陷返修及完整任务恢复 | S3、S4、S6 及相关参数组合通过；固定负载达到设计预算 |
| M4 原生适配与独立交付 | 获准的转换实现、VTS API、运行映射、离线播放器与工程包 | S5 在相应实际环境通过，T08 完成 Studio/离线播放器对照，所有运行依赖来自交付清单 |
| M5 开源首个正式发行 | 许可与贡献、干净构建、支持矩阵、安装包、文档及发行回读 | 功能、兼容和独立运行测试完成，分发内容符合许可 |

安全边界、许可分类、类型检查和内容分工从 M1 实施，后续阶段验证新增的调用与资源路径。M1 的最小 Studio 只承担工程选择和编辑闭环，完整界面随 M2—M4 的实际能力接入。M2/M3 完成共享求值、分组与遮罩渲染及资源释放的阶段检查，REQ-08 的完整验收在 M4 纳入正式离线播放器。原生许可和转换可行性在早期验证，避免到最终打包才发现依赖。

## 3. 开发工作切片

每个工作项关联[需求正文](../product/requirements.md)中的稳定需求和[验收场景](../testing/strategy.md)，模块与阶段使用[需求关联数据](../product/requirements.json)，给出负责模块、输入、输出、必要依赖、实际状态及验收环境。完成一个可运行切片后再推进其消费者。

优先切片是“新工程—直接编辑—候选—原子应用—重启恢复”，随后接入真实素材和表现。任何自动化能力都必须能通过相同公共命令执行和核对；不得把角色专用脚本作为公共功能的隐含入口。

跨阶段变更先计算影响集合。已经覆盖且未变化的检查沿用原结果；新实现、接口、格式、目标平台或打包变化触发对应补验。

## 4. 阶段完成与交接

M0 交付项目设计。后续各阶段分别记录实现对象、实际执行的验收、候选包、运行环境和需要的决定。目标软件与作品画面由对应实际运行和评审取得结论。正式发行按准确源码、制品和渠道回读收尾。
