# Riloom Studio

面向交互设计与 Studio 开发，定义画布工作区、编辑反馈、快捷键及可访问性。

## 1. 工作区与视觉语言

统一 Web 工作台以画布为中心，采用冷灰石墨底色、蓝紫强调色、清晰的层级和紧凑控件。主要制作功能保持在同一工程会话中。

| 区域 | 职责 |
| --- | --- |
| 顶栏 | 工程名称、保存状态、历史入口、撤销/重做、命令搜索 |
| 左侧 | 部件、图层、控制树、素材与查找 |
| 中央 | 工程视口；候选对照、网格/遮罩与定位 |
| 右侧 | 当前对象属性、参数、工位配置 |
| 底部 | 动作时间轴、曲线、任务进度及结果 |
| 工作区切换 | 制作、动作、物理、联调、交付 |

## 2. 编辑状态与反馈

技术详情提供工程修订、请求回执和错误码。常用编辑界面围绕对象名称、保存状态和可执行动作呈现反馈。

工程持久状态、保存草稿、视口临时状态、任务状态和目标软件状态分别管理。画布拖动即时反馈，手势结束形成新的编辑代次并发起[草稿保存](../reference/commands-and-tasks.md#draft-persistence)。保存中、草稿已保存和草稿已应用分别对应在途请求、当前代次持久确认和模型事务完成。后续输入产生新代次，保存完成只确认其捕获的输入。已应用或丢弃草稿保留终结版本，后续编辑建立新草稿。

<a id="default-edit-flow"></a>

### 默认编辑与应用入口

顶栏与命令搜索提供“应用草稿”，旁边提供“查看更改”与差异预览入口。“保存草稿”和保存快捷键确认当前草稿的持久版本。当前代次已保存且存在待应用修改时显示“草稿已保存，待应用”。默认应用范围为本编辑会话当前草稿的完整 ChangeSet，覆盖制作、动作和物理工作区积累的修改，当前选区只决定后续编辑对象。

1. 点击“应用草稿”先结束当前手势并校验输入控件，捕获本次操作前缀与 editGeneration。等待已有保存回执核对完成，再按当前 expectedDraftVersion 保存该固定前缀。
2. 保存确认后，用确认的 draftId、draftVersion、基线修订和状态身份准备候选。按钮显示实际准备或应用进度，差异入口可查看本次固定范围。轻量编辑同步准备后直接提交，使用同一次应用操作。
3. 应用事务同时核对草稿和工程前提，提交模型、逆操作、回执、事件及草稿 applied 终结版本，一次默认应用建立一个已封口工程撤销组。无更改或输入校验失败时说明具体条件。
4. 应用期间的新增输入保留为后续操作序列，固定草稿暂停其他保存。本会话保持一个在途模型提交。成功后扣除已应用前缀，以返回修订建立新草稿并保存剩余输入，后续逆操作以已应用结果为前值。

保存确定失败时保留固定前缀及后续输入，停止本次模型应用。保存或应用结果未知时先按原请求核对，同一操作重投沿用原 requestId。模型或草稿冲突保留草稿、候选及后续输入，提供差异和重新准备入口，重新取得对应前提后才提交。

切换工程先结束手势并停止原工程新增制作输入，核对在途应用结果，再保存当前草稿或应用后的剩余输入。持久确认后完成切换，失败保留原上下文。普通切换保留已保存的待应用草稿，返回原工程时恢复其差异预览。

活动草稿的撤销重做按手势序列执行，撤销到起点后仍可重做。应用期间只撤销固定前缀之后的本地输入，跨越该边界的操作等待原结果，成功后按新草稿或工程历史定位，失败后回到保留草稿的手势历史。应用成功且后续草稿为空时，画布撤销进入工程共享历史。

### 连续自动提交

高级用户可开启连续自动提交，每个编辑会话最多有一个在途模型提交，后续输入继续即时预览并积累到待提交操作序列。会话按顺序派发模型提交和手势封口。前次结果确认后扣除已应用的编辑前缀，以返回修订另存新草稿并准备下一候选，按[共享历史规则](../reference/commands-and-tasks.md#undo-history)聚合连续提交。遇到工程或历史冲突时暂停该手势后续模型派发，保留当前草稿与预览输入，显示差异并提供重新准备入口。

### 工程切换与候选反馈

切换工作区保留选中对象、时间、视角和草稿。切换工程按[默认编辑流程](#default-edit-flow)核对在途应用并保存当前输入。任务继续绑定原工程。刷新按 draftId 读取服务端已确认版本与任务，再恢复本地视图偏好。页面显示具体草稿保存状态，浏览器关闭或刷新接入其支持的离开确认机制。

冲突页面展示受影响对象、用户草稿及当前修订，提供“保留草稿并重新准备”和“查看差异”；不以覆盖按钮静默丢失并发编辑。数据损坏显示具体受影响素材及可用恢复来源。日志和堆栈放在技术详情中。

候选页面显示前后画面、保护区域、修改对象、诊断与应用动作。失败候选只显示诊断及修改输入入口，应用按钮不可用。

## 3. 各工作区

- **制作**。直接编辑与工位并列，选中对象过滤适用工位。补画依次提供准备 PNG 副本、查看实际可编辑与保护区域、选择返回文件、检查回位及最终差异、应用候选。图像提供方由同一入口显式选择。常用表单使用画布选区、对象树和类型控件，复杂配方保留高级结构化编辑。
- **动作**：轨道、参数单位、Bezier 手柄、循环边界和事件清楚可见；支持定位缺陷时刻、同种子重放及持续输入叠加。
- **物理**：输入、粒子和输出分区；展示预热、时间步和轨迹，修改形成候选。实时预览与离线完整采样各有入口。
- **联调**：选择目标软件和具体模型；画面来源、控制目标、追踪输入和模型输出分别显示。表情、衣装和嘴型由状态组呈现。取图按次执行，截图带实际目标与时间。
- **交付**：选择内容和格式 → 展开依赖 → 运行转换与检查 → 查看分项结果 → 组装 → 打开产物目录。编辑工程、运行模型和验收资料分别取得。

## 4. 交互与可访问性

键盘支持焦点导航、命令搜索、树选择、数值编辑、时间轴移动及标准撤销。文本框由文本编辑器处理撤销，活动草稿按手势操作序列撤销或重做并保存为新代次。草稿成功应用且没有后续输入，或显式丢弃活动草稿后，画布撤销进入工程共享历史，历史入口展示目标组和受影响对象。快捷键从同一动作目录生成，支持冲突提示、键盘区分与自定义。输入框获得焦点时不触发模型动作。

拖动操作提供数值输入替代，图标按钮具有名称，禁用控件说明具体条件。长列表虚拟化仍保持逻辑焦点。颜色对比、200% 缩放、减少动画偏好和屏幕阅读器下的关键流程进入界面验收。

## 5. 预览资源和事件

React 管理面板状态，renderer 管理动画循环与 GPU 资源，高频姿态不触发整个组件树重渲染。后台页签降帧或暂停显示，离线任务继续使用其规定时步。首次打开、断线重连和回到前台时，按[查询与事件契约](../reference/commands-and-tasks.md#queries-and-events)取得同一读事务的当前状态与事件游标，再从该游标之后续接。客户端按流和序号去重，游标过期时重新取得状态与游标。任务、草稿和评审等列表按[集合版本](../reference/commands-and-tasks.md#collection-pagination)续页，页面响应按当前查询世代接纳，条目更新按 recordVersion 接纳。

Studio 和便携播放器共用 evaluation/renderer；候选预览在独立模型状态上求值。加载失败、WebGL context loss 和设备资源不足提供恢复、降低显示分辨率或导出离线检查图的具体操作，模型数据保持原精度。


## 6. PNG 图层编辑

制作区的图层加号选择 PNG 文件，导入后选中新绘画。左侧图层列表按显示顺序排列，显隐按钮直接编辑草稿。右侧提供名称、位置、不透明度、上移、下移和删除。删除绘画后，素材继续由工程及历史引用保留。

画布使用 WebGL2 浮点合成，提供适合画布、放大和缩小。点击可见像素选择绘画，选择轮廓覆盖完整素材画框。图形上下文恢复后重建纹理和合成资源。工程切换及组件卸载释放相应资源。

PNG 导入先等待当前草稿保存，再追加素材和绘画。从保存开始锁定当前工程会话，完成导入或结果核对后恢复工程切换。响应中断时保留原导入请求、草稿身份和编辑基线，后台刷新在结果核对完成后继续。使用“核对导入结果”取得原结果。参数和图层共用草稿、应用、冲突处理与工程历史。

可见图层超过设备支持的纹理边长时，视口显示图层名称、尺寸和设备上限，提示缩小或拆分图层。隐藏该图层后恢复其余图层的显示。纹理上传失败后释放临时资源，再次绘制时重新上传。成功后清除绘制错误，素材读取错误独立保留。
