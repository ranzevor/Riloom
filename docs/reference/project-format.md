# 数据与工程格式

供核心、存储和适配器开发者查询工程对象、坐标、存储及格式演进约定。

## 1. 权威对象与标识

| 对象 | 内容及不变量 |
| --- | --- |
| Project | 工程身份、格式版本、修订、画布、对象集合及扩展 |
| Asset | 原始文件、原始解码像素、工作副本、来源、许可引用、画框及颜色转换配置 |
| Part / DrawItem | 分组、绘画、合成边界、遮罩、显隐、局部透明度、基础层序和稳定同层顺序 |
| Mesh | 顶点、UV、三角索引及素材引用；顶点与 UV 一一对应 |
| Controller | 几何语义版本、Rotate / Warp 模式、父控制、可逆仿射绑定、局部属性及笼分片 |
| Parameter | 稳定身份、名称、单位、最小/默认/最大值；全部数值有限 |
| Keyform | 几何语义版本、目标属性块、有序轴、grid-linear / simplex-linear 数据及域外策略 |
| Motion / Expression | 曲线、混合模式、通道所有权、循环和状态进入/退出规则 |
| VariantGroup | 衣装、嘴型、配件等通用状态组；约束与默认选项由数据定义 |
| PhysicsSystem | 求解器版本、解析后默认值、链静止向量、初态、输入输出映射、时步、预热与反馈策略 |
| Candidate / Recipe | 来源修订、差异操作、保护约束、生成器和素材引用 |
| Draft | 独立身份、种类、基线、保存版本、编辑代次、手势操作、历史游标、补画准备及素材引用 |
| Defect / Review | 对象、姿态/时间、产物身份、判据、评审结论与修复关系 |
| Delivery | 源修订、配置、依赖闭包、准确文件清单及分项验收 |

对象 ID 使用不含业务含义的稳定标识；中文名、英文名和外部参数 ID 分别存储。对象名称可以修改和重复。核心语义使用命名空间标签与显式关系，允许自定义标签。不得通过英文字符串推断表情情绪或把中文名称作为主键。

## 2. 坐标、数值与渲染契约

- 工程坐标单位为像素，画布左上为原点，x 向右、y 向下；旋转角以度表示，正值为顺时针。局部变换采用列向量和父矩阵乘子矩阵。
- 时间单位为秒。曲线端点、Bezier 手柄、循环接缝及插值类型显式存储。离散状态使用阶跃插值。
- UV 的 (0,0) 为源纹理左上，(1,1) 为右下；像素中心为 (i+0.5)/width、(j+0.5)/height。图集映射与目标软件翻转由导出器一次完成。
- 图像原始文件、原始解码像素与工作副本分别引用，按[颜色与像素保留](#color-management)处理。渲染在线性 sRGB、预乘 Alpha 下混合，显示与导出使用明确的输出色域。
- 低 Alpha、描边和保护区域保持像素完整；几何优化不得隐式改纹理。派生图像同时记录来源文件摘要、解码像素摘要和变换。
- drawOrder 可随参数变化；同值时按持久 orderToken 排序。orderToken 在一次排序编辑中原子更新，重开和导出保持确定顺序。
- 持久数值使用 JSON 可精确表达的有限数值；求值使用 IEEE 754 双精度，GPU/目标格式的 Float32 转换检查误差。数组可存为有版本、有字节序和长度的二进制 blob。
- 分组与遮罩按[合成边界与遮罩采样](#compositing-and-masks)保存和求值。导出器逐项声明支持。不支持的效果输出对象级诊断。

<a id="color-management"></a>

### 颜色与像素保留

Asset 保留原文件字节、未经颜色变换的完整解码通道、位深、Alpha 表示及嵌入色彩配置。解码引用与颜色配置共同解释原始像素，透明像素的 RGB 也予以保存。PNG 缺少色彩配置时按 sRGB 解释，并登记此输入条件。存在多项颜色元数据时按输入格式规定的优先级解释，选定配置损坏时返回具体输入错误。

首版工作副本使用 sRGB 编码和直通 Alpha。非 sRGB 输入通过固定实现及版本的 ICC 相对色度转换生成工作副本，关闭黑点补偿。转换配置固定源/目标配置、渲染意图、输出像素格式与舍入规则，并随素材保存。Alpha 不参与颜色变换。以未裁切转换结果检查目标色域，默认拒绝超出 sRGB 色域的转换，诊断定位素材及超色域范围。制作者明确选择 clip-srgb 后生成新候选，将转换后的线性 RGB 各分量裁切到 [0,1]，再按 sRGB 编码写入所选像素格式。源文件和原始解码引用持续保留。

sRGB 素材沿用原通道与精度，几何和分层操作以实际工作副本为像素保护基线。颜色转换候选分别给出原始像素保持与转换结果比较，转换后的 RGBA 不与转换前数值混作同一判据。renderer 解码 sRGB 后预乘 Alpha，在线性空间执行 source-over，显示输出编码为 sRGB 并声明对应色域。目标格式使用同一已选工作副本和输出配置，额外转换作为显式候选处理。

<a id="compositing-and-masks"></a>

### 合成边界与遮罩采样

分组保存 compositeMode。Normal 隔离组使用 isolated，子项先在透明背景上按组内层序合成，再对整组预乘颜色与 Alpha 各施加一次组透明度及组遮罩。该组作为一个整体按自身 drawOrder 与 orderToken 进入父组，子项层号只影响组内顺序。嵌套组逐级应用各自边界。PSD Pass Through 及其他混合效果由导入能力逐项匹配。缺少等价求值时返回 UNSUPPORTED_FEATURE，并提供制作者可选择的烘焙候选及具体编辑性损失。

遮罩引用明确源、目标、反相标记、combineMode 与 alphaScope。源采样使用同一姿态下完成自身几何、素材 Alpha、局部透明度、显隐及自身遮罩后的覆盖 Alpha，发生在与场景背景混合之前。组作为源时先完成其内部合成。alphaScope=local 排除祖先组的透明度、显隐和遮罩，global 继续乘入这些祖先因素，默认使用 local。源对象自身隐藏时其源 Alpha 为 0。

每个输入先按反相标记得到 a 或 1-a。intersect 的结果为各输入乘积，union 为 1-Π(1-a)，单一输入直接使用该值。得到的遮罩覆盖率同时乘入目标的预乘颜色与 Alpha 一次。目标没有遮罩关系时覆盖率为 1。分组透明度保持在组的合成阶段施加，不能再向各子项重复分发。

求值器在绘制前为自身遮罩、组内合成及 global 的祖先依赖建立完整依赖图，按拓扑顺序计算源覆盖率。遮罩源可位于目标之后的显示层序。缺失源或任何依赖环在候选校验时拒绝，诊断给出对象与依赖链，当前模型保持。导入与转换按该采样阶段核对嵌套遮罩。

### 制作算法与补画元数据

Controller、Mesh 和 Keyform 的几何配置遵循[控制与关键形算法](authoring-and-evaluation.md#deformation-algorithms)，重布网在 Mesh 中保留逐新顶点对应及 preservationMode，沿[重布网合同](authoring-and-evaluation.md#remesh-mapping)校验完整表面。PhysicsSystem 保存 riloom.particle-chain/1 和全部解析后的参数，初态、根输入及输出单位按[粒子链规则](authoring-and-evaluation.md#particle-chain)解释。缺少必需版本或配置时定位具体字段，未知版本沿既有扩展与能力规则处理。

补画草稿的 paintPreparation 保存来源身份、drawItemId、源 Asset 与工作像素引用、画框/原点、E/P 掩码、PNG 格式和双向转换及回位配置。草稿 kind 与这些准备字段在创建后固定，修改只读字段返回 INVALID_INPUT，调整补画范围时新建准备。回导只更新版本化 ChangeSet、候选和输入引用。派生 Asset 的来源关联准备、返回素材及选定转换，全部引用进入草稿、候选和历史的保留闭包。自有不可变编辑副本与制作者另存的可编辑文件分别管理。

## 3. 工作工程与交换包

工作工程是自包含目录：

~~~text
MyCharacter.riloom/
  project.sqlite             当前状态、历史、草稿、任务、回执和评审
  assets/sha256/ab/<digest>   不可变原始素材及必要衍生数据
  artifacts/<jobId>/          已登记候选及报告
  staging/<operationId>/      未发布的中间文件
~~~

工作区目录使用 workspace.sqlite 保存工程登记、工作区命令回执、工作区级任务、外部安装意图、用户布局和插件登记。模型安装任务的受理、阶段和结果归属工作区，工程制作任务归属对应工程数据库。凭据仅保存安全存储引用。工程模型与历史均位于工程目录。复制或移动工程使用一致性备份操作，恢复按[备份恢复与工程身份](#backup-recovery)接替登记。活跃 SQLite WAL 文件不可由普通文件复制拼成备份。

交换文件扩展名为 .riloom.zip，内含 manifest.json、project.json、assets/、必要 artifacts/ 和 rights.json。manifest 登记 formatVersion、producer、profile 及[载荷文件清单](#exchange-manifest)。project.json 可独立描述模型。交换包支持编辑状态和选定历史两个 profile，默认保留当前模型及必要素材。交换包导入建立新的 projectId，包内原工程身份保留为来源信息，对象 ID 与内部引用保持。选定历史仅包含模型操作与逆操作。原请求账本、后台任务、外部操作、目标绑定与授权均不注册为新工程的可执行状态。

<a id="exchange-manifest"></a>

### 交换包清单

ZIP 成员类型限定为常规文件和目录。根 manifest.json 的 files 精确登记载荷文件集合，载荷集合定义为 ZIP 常规文件集合减去根 manifest.json。每项包含规范化相对名称、SHA-256、字节数、媒体类型与逻辑作用，摘要和字节数对应解压后的原始文件字节。根清单按自身 Schema 校验，目录条目按[文件与解析规则](../security/design.md#3-文件与解析)校验。

组装先完成载荷及其条目，再写根清单并封装 ZIP。导入核对清单结构、条目唯一性、实际载荷集合和逐项内容。project.json、rights.json 及所选 profile 的全部依赖进入载荷清单。缺失文件、额外常规文件、重复名称、错误长度或摘要均返回 DATA_CORRUPT，并定位具体条目。

所有文件摘要使用带算法标识的结构 { algorithm: "sha256", digest: "…" }。来源 BLAKE3 等摘要保留在 provenance；导入先按原算法核验，再对实际字节生成新摘要。禁止仅替换算法标签。

### PNG 与绘画的数据格式

工程 1.1.0 在参数集合之外保存 assets 与 drawItems。Asset 的 source 指向原始 PNG，pixels 指向完整 RGBA 解码通道，二者通过内容地址引用工程 assets 目录中的不可变文件。引用包含算法、内容值与字节数，16 位像素为小端 RGBA16。

绘画保存素材引用、原点位置、名称、显隐、不透明度和稳定层序。绘画初始覆盖素材的完整矩形，像素范围与画框分别处理。预览在线性 sRGB 中执行预乘 Alpha 合成，再编码为 sRGB 显示。

工程 1.0.0 继续保持原结构和状态身份。首次导入素材时，setFormat 操作将其升级到 1.1.0。对应逆操作在素材和绘画集合为空时恢复原格式。工程数据库版本 2 增加 blobs 登记表，打开版本 1 时在事务中升级。

素材先以完整文件发布，再与草稿或模型引用一起登记。备份复制一致性数据库内登记的全部素材，覆盖当前模型、历史、候选和草稿引用。复制后验证字节、内容、文件集合和数据库登记。恢复后的素材由新工程目录独立提供。

## 4. 持久化与原子提交

SQLite 保存 projects、revisions、objects、operations、receipts、drafts、jobs、job_steps、artifacts、reviews、external_operations、events。关系以外键及唯一约束表达。草稿内容、操作序列、draftVersion 与终结状态按[草稿契约](commands-and-tasks.md#draft-persistence)保存，保留基线与素材引用。列表版本按[集合契约](commands-and-tasks.md#collection-pagination)与所属数据共同提交。项目当前修订、编辑记录、逆操作、回执和对应事件在一个数据库事务内提交。后台任务受理将操作认领、job 和受理回执写入同一所属数据库事务，派发从已提交的任务读取。任务最终发布与取消的提交次序遵循[命令契约](commands-and-tasks.md#4-错误与取消)。

素材与数据库采用先文件后引用协议：

1. 在本操作 staging 目录完整写入 blob，检查字节数、解码和摘要，并同步文件。
2. 移入内容地址目录；已有同摘要文件先核验完整字节。完成平台支持的持久化步骤后才进入可用引用的提交事务。
3. 提交对象引用、修订、回执和事件。返回成功必须在持久提交后。
4. 文件成功但数据库失败产生无引用 blob，可按保留期回收；数据库不得引用半写文件。
5. 打开工程检查 SQLite、引用闭包及摘要。发现损坏进入只读恢复，保留损坏对象，使用已核备份或重新取得的同身份 blob 修复。

单工作区服务串行执行每工程写事务；并行客户端通过 expectedRevision 与 expectedStateHash 比较提交前提。SQLite 是最终事务约束，进程内锁用于调度。

stateHash 是 ProjectState 经 RFC 8785 JCS 规范化后计算的 SHA-256。ProjectState 包含完整模型对象、对象 ID、依赖引用和带算法的 blob 身份；数组次序有语义。进入规范化前拒绝 NaN、Infinity 和 -0，使用 UTF-8 并提供跨语言黄金向量。布局、草稿、历史导航元数据、集合版本、日志、任务、评审及处理时间戳存于模型状态之外，避免循环引用及视图变化影响模型身份。

工作区创建/登记工程跨越目录与两份数据库，使用持久意图：先登记 creating 及固定目标 → 在自有新目录建立并核验工程 → 发布完整目录 → 完成工作区登记和回执。重启按原意图与目录归属核对完成或清理；不承诺跨文件与数据库的单一事务。已有外部工程的打开只登记经核验引用，不自动迁移其位置。

## 5. 版本、扩展和恢复

工程格式从 riloom.project/1 起建立显式版本。扩展的保留、引用和写入能力遵循[扩展引用与编辑兼容](#extension-compatibility)。

<a id="extension-compatibility"></a>

### 扩展引用与编辑兼容

扩展条目包含 extensionId、version、required、payload 和 references。核心可解析的 references 分列 objectIds 与 resourceRefs，前者定位工程对象，后者使用既有素材或产物引用。空数组声明该类依赖为空。扩展生产者将跨对象和资源依赖完整登记在 references 中，扩展通过引用标识定位依赖，payload 保存扩展自身数据。宿主核对声明结构和目标，并将声明依赖纳入引用闭包。

导入核对声明结构、对象存在性和资源闭包。已识别封套的声明字段缺失或已声明目标缺失时返回 DATA_CORRUPT，定位具体字段或依赖。未知可选扩展在引用声明可解析且完整时支持往返，payload 的值、数组顺序、未知字段与声明完整保留。显示名称修改、视口调整及与其依赖无关的编辑沿用原条目。修改被引用对象的数据或结构时，相容处理器由已注册的格式适配能力提供，声明支持的 extensionId 与 version，输出新的 payload 与引用声明，并随整个 ChangeSet 校验。缺少处理器时返回 UNSUPPORTED_FEATURE，指出扩展、依赖对象和冲突操作。

制作者可选择安装相容处理器，或在候选差异中显式移除该可选扩展后继续。移除、对象修改及逆操作共同提交，逆操作保留完整扩展和引用。导出、备份、历史与资源回收均遍历扩展 references。

未知必需扩展或含有无法解释引用类型的扩展使工程进入受限读取。此模式提供元数据查看、校验与完整导出，原包文件集合保持保留引用。模型编辑及会改变原包成员的维护操作返回 UNSUPPORTED_FEATURE。普通往返保存保留未知字段，显式移除使用上述变更契约。

格式升级在新副本上运行：备份 → 校验 → 迁移 → 引用和语义对照 → 发布新工程。保留原副本和版本映射；有损降级必须给出明确丢失项，由用户选择对应导出方案。

Undo/redo 按[撤销重做与手势聚合](commands-and-tasks.md#undo-history)创建新的受保护模型修订，共享历史组、historyVersion 和游标与模型结果同事务提交。历史恢复通过操作日志和逆操作建立新修订，请求去重账本及外部操作保持连续。

<a id="backup-recovery"></a>

### 备份恢复与工程身份

一致性备份固定同一数据库读视图，并在备份完成前保留该视图的全部资源闭包。备份包含工程模型、历史及操作账，工作区安装意图和会话授权保持工作区归属。恢复先在自有新目录完成数据库、资源与格式校验，再接替登记。

备份恢复保留 projectId。同一主机、同一用户范围内，该身份只允许一个可写所有者，以[工程身份锁](../architecture/overview.md#workspace-ownership)协调跨工作区持有。工作区内同一 projectId 只登记一个当前目录。异目录恢复接替先释放原所有者，再原子更新当前登记并分配新的 storageGeneration，存储世代属于存储与授权元数据。冲突副本仅能隔离读取，不进入按 projectId 路由的可写集合。现有客户端按新存储世代重新取得授权并读取状态，旧世代请求被拒绝。

同一存储的崩溃重启沿原账本接续。备份恢复则先登记恢复屏障，备份中含外部步骤且可继续的任务先进入 reconciling，包含原记录为 queued、派发记录为空及允许恢复的 failed 任务。原取消意图保持。恢复副本不自动派发这些步骤，旧目标绑定失效。逐外部步骤按原操作身份、有效回执、实际目标结果及当前授权核对。已发生且结果可确认的步骤补齐或复用原结果，确认未发生的步骤在显式恢复后按当前授权派发，结果未知的步骤保持 reconciling 并禁止重发。待继续步骤的效果、费用、期限及版本前提核对完成后，可显式恢复剩余步骤。原取消意图继续阻止派发。

备份截止之后的外部消费由原操作查询或提供方结算补齐。核对完成前，备份消费值作为已知下界，相关任务的外部可用额度为 0。新增预算须经明确授权，原未决动作继续按原身份核对。无外部副作用的步骤可在资源完整及原版本可用时按任务契约恢复。历史回执保留其原结果，目标当前状态通过新回读取得。

### 工程备份格式

工程备份采用 .riloombackup 目录。riloom.backup/2 包含 backup.json、独立的 project.sqlite 和 assets 素材目录，清单列出全部已登记素材内容。riloom.backup/1 的参数工程备份继续可读。清单记录备份身份、工程名称与身份、模型修订、模型状态及数据库长度和内容校验值。读取时核对完整文件集合、数据库格式、模型、历史正逆操作、草稿、候选和回执。导入将选定备份复制到当前工作区，再校验复制后的内容。

备份通过 SQLite 的 VACUUM INTO 获取一致性数据库，工作区保存创建意图后生成文件，完整校验后发布备份目录并提交备份登记与回执。恢复将数据库复制到自有中间目录，更新存储世代，完整发布新工程目录后接替登记。原工程目录继续保留。

备份和恢复的文件发布与登记均采用持久意图。中断后按原请求接续，目录已完整发布时复用其内容。恢复后的工程写入携带当前存储世代，阻止旧编辑请求进入恢复结果。工作区数据库从版本 1 原子迁移到版本 2，工程数据库保持版本 1。
## 6. 保留与资源回收

<a id="resource-lifecycle"></a>

回收根包括当前工程、保留中的候选及其来源与派生素材、有效草稿、保留历史及逆操作、排队或可恢复任务、检查点、交付和评审。正在发布的资源与读取者持有的资源一并保留。候选经显式丢弃或达到已选保留期限，并解除所有占用后退出保留集合，已应用结果由工程和保留历史继续持有。

### 发布、引用与删除协调

资源可用状态、保留引用和删除意图保存在存储元数据中。资源发布、保留引用的新增/解除、读取占用与回收共用所属工程的存储锁，锁顺序固定为存储锁后数据库写锁。暂存计算在锁外执行，完整资源的发布及可用引用提交在持锁期间完成。发布前持久登记操作意图、预期内容身份及保留集合，完整文件发布后提交可用资源引用。

服务派发任务或提供文件流前取得输入资源的保留引用。短时读取持有至流关闭，任务持有至相应执行世代退出且在途结果已核对。服务重启先恢复发布意图、任务占用和未决删除，再开放对应资源的新增引用与回收，旧执行者的占用按实际退出状态处理。

1. 根据保留策略、工程前提和引用闭包生成删除计划，列出具体自有文件与理由。
2. 执行每个条目前取得存储锁，重读当前保留引用、发布预留和读取占用，并核对实际文件身份。新增引用或占用的条目作为保留项返回。
3. 合格条目在同一所属数据库中持久登记逐项删除意图及 deleting 状态，再执行文件删除，随后提交资源注销与该项结果。新增引用等待存储锁，并在锁内核对资源可用状态。
4. 中断后按原维护操作逐项核对。删除已发生时补齐注销，删除尚未发生时重查保留条件后继续或撤销本项意图。文件占用等已确定失败保留该项与具体原因。结果仍在核对的资源返回 RESOURCE_BUSY，核对完成后开放后续访问。
5. 同请求重投按[写入封套与回执](commands-and-tasks.md#2-写入封套与回执)返回原回执，异步结果通过原 jobId 查询，恢复复用已完成条目。新计划仍按当前引用核对。重新发布同一内容身份前先完成原删除意图的核对与注销。

已按计划回收的旧引用返回 RESOURCE_GONE，调用方重建可重建产物或重新导入对应素材。有效保留引用对应文件缺失时返回 DATA_CORRUPT。清理 staging 只处理归属明确、执行已结束且保留引用已解除的目录。备份和正式交付按各自保留策略管理。
